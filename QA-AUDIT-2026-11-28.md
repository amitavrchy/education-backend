# QA and product audit — 28 Nov 2026

Senior QA and product review of ShikkhaAI across all four repos (`education-ai`, `education-backend`, `education-frontend`, `education-flutter`), done before selling it.

## Verdict

**Not ready to sell to paying customers yet. Close enough to run a controlled pilot.**

The core product works end to end on real data:
- AI tutor, book avatar, photo solver, exams, notes, flashcards, planner, English coach, payments flow and admin.
- A real NCTB textbook (SSC Physics, 366 pages) is ingested; answers cite real pages.
- Security basics held up under probing.

What blocks a paid launch:
- Infrastructure that is still on free or dev settings (AI quota, SMS, email domain, storage).
- Content that is still synthetic (four of five textbooks, board papers).
- Legal and marketing copy that still says "demo".

## Fixed during this audit

1. **Security — password change accepted any current password.** Demo mode's "any password works" sign-in shortcut also applied to `POST /auth/change-password`. The endpoint now always checks the real password hash. QA's own test had changed the demo student's password; it was restored.
2. **Reliability — one model's daily quota took every AI feature down.**
   - The main model (`gemini-3.5-flash`) hit its free-tier daily limit, and the previous day's fix had stopped the fallback to other models.
   - Calls (normal and streaming) now move through a model chain: main → fast → `GEMINI_FALLBACK_MODELS`.
   - Covered by new tests; the AI features were verified working again.
3. **Production safety.**
   - The backend now refuses to start in production with `SMS_PROVIDER=console` or `EMAIL_PROVIDER=console`; with those settings, codes would never be delivered.
   - `SMS_PROVIDER=none` now fails visibly instead of pretending an OTP was sent.
4. **UX — raw server errors reached users.** Students saw "ThrottlerException: Too Many Requests". The error mapper now gives Bangla messages for throttling, AI busy or quota, server errors and OTP delivery, and never shows exception text. The network-error message no longer says "(demo simulation)".

## P0 — must fix before charging money

1. **AI capacity and cost.**
   - Every AI feature runs on the Gemini free tier. After about a day of development testing, the main model and the embedding model had both used up their daily quotas.
   - Real customers need a paid Google AI Studio or Vertex project (pay-as-you-go) with billing alerts.
   - Use the token counts in `aiLogs` and the per-plan usage limits (`UsageService`) to set prices that cover AI cost.
2. **Phone sign-up has no SMS gateway.**
   - Only `console` and `none` exist, so phone OTP cannot work in production. Most Bangladeshi students sign up with a phone number.
   - Fix: add a local gateway adapter (SSL Wireless, BulkSMSBD or Alpha SMS) behind `SmsProvider`. This needs an account and a sender ID.
3. **Email sender.** `EMAIL_FROM=onboarding@resend.dev` delivers only to the Resend account owner. Verify your own domain in Resend and set `EMAIL_FROM`.
4. **Demo mode and demo data.**
   - Production requires `AUTH_DEMO_MODE=false` (enforced).
   - Set `SEED_ON_EMPTY=false`, or seed only the curriculum. Otherwise production starts with synthetic users, payments, schools and demo accounts.
5. **File storage.** `STORAGE_PROVIDER=local` stores uploads on one server's disk; a redeploy or a second instance loses them. Use S3 or Cloudflare R2.
6. **Payments.** Manual bKash/Nagad verification works, but no payment numbers are configured, and a person must verify every payment. Fine for a pilot. For scale, apply for a bKash/Nagad merchant API (PGW).
7. **Legal copy.**
   - The privacy policy says "students of any age can sign up without guardian permission". For a minors' product, this needs a lawyer's review against Bangladesh's data-protection rules, and probably guardian consent below a set age.
   - Terms and privacy need the company name, address and contact details.

## P1 — fix before a public launch

1. **Content is mostly synthetic.**
   - Only Physics is a real textbook.
   - Chemistry, Biology, Maths and Higher Maths are downloaded but not yet ingested (run `scripts/ingest-nctb.sh`).
   - The other 26 books, all board and institution question papers, and the school list are still synthetic. Students will notice quickly.
   - Licensing: NCTB holds the copyright to its textbooks. Get written permission, or confirm that use is allowed, before selling access to them.
2. **"Demo" copy that customers will see.**
   - Pricing: "Demo prices — not real pricing".
   - Testimonials labelled "demo persona".
   - FAQ answers that say "this demo".
   - The contact form is simulated (`mockRequest`); it should create a support ticket.
   - The Flutter app: same review needed.
3. **Book chapter coverage.** The curriculum lists 8 Physics chapters, but the NCTB book has more. Unlisted chapters get folded into neighbouring ranges (for example, refraction falls under "আলোর প্রতিফলন"). Bring the curriculum chapters in line with the 2026 NCTB books.
4. **Flutter is behind the web app.** The phone app still lacks:
   - real book pages
   - note upload through the server
   - recorded pronunciation
   - AI planner and AI flashcards from text
   - leaderboard and challenges
   - password, 2FA and sessions
   - support tickets
   - handling of the `otpRequired` login response (2FA users cannot sign in on the app)
5. **Operations.**
   - No error monitoring: add Sentry or similar to all three services.
   - No Dockerfile for the AI service or the web app.
   - CI does not run the tests; the deploy workflow exists only for the backend.
   - No database backup plan.
6. **Unverified paths.**
   - Browser webm recordings sent to Gemini for pronunciation.
   - Invitation emails and parent report emails (Resend sandbox).
   - The KB reindex button in the UI.
   - The public page for shared tutor conversations; the backend endpoint exists, the page does not.

## P2 — polish

- Leftover "simulated" labels:
  - the avatar page badge
  - the audio-lesson dialog title
  - the notification centre's "simulate" button
  - the admin-system data-export note
  - the admin KB reindex toast
- Onboarding institution suggestions are hard-coded "(demo)" names; use the institutions list.
- The leaderboard and analytics compute from seeded activity until real usage exists. Seeded students all show the same XP.
- Offline downloads on the web are a simulation. Keep it, label it as preview, or build a real service-worker cache.

## Strengths worth selling

- AI is grounded in textbook pages with citations, and the Bangla avatar and TTS work.
- Answers and grading come with honest confidence and teacher-review labels.
- Separate portals for student, parent, teacher and admin.
- Manual bKash/Nagad/Rocket/Upay payment with admin verification.
- The admin ingestion pipeline turns any PDF, photo, Word or Excel file into searchable knowledge.
- Accessibility checks pass.
- Clean separation between the AI service and the backend.
